## 1. Общий обзор контекста
Core List — это ядро FPGA, которое предоставляет CPU список ядер FPGA, которые в настоящее время инстанцированы в данной версии FPGA. Предполагается, что CPU обращается к Core List во время запуска, чтобы либо проверить, либо правильно установить диапазон адресов для каждого экземпляра ядра FPGA, маски прерываний и т.д.
Процесс предоставления списка ядер CPU:
- Текстовый файл Core List создается вручную перед компиляцией FPGA design. Он содержит информацию о ядрах FPGA в предопределенном формате.
- Текстовый файл загружается в FPGA во время компиляции. FPGA хранит файл как ROM.
- CPU может считывать информацию Core List, обращаясь к регистрам AXI ядра CoreList.

## 2. Описание интерфейса
### 2.1 Core List IP
Интерфейс Core List:
- System Reset и System Clock на входе
- AXI4L slave интерфейс, через который CPU считывает информацию Core List (базовый адрес должен всегда находиться по фиксированному адресу, чтобы программное обеспечение знало, где его искать)
- Sticky flag на выходе, указывающий, что список был прочитан CPU

Параметры конфигурации ядра:
- Период System Clock в наносекундах
- Локальный путь к текстовому файлу, содержащему Core List

### 2.2 Текстовый файл Core List
Текстовый файл Core List — это конфигурационный вход для ядра Core List. Путь, имя и содержимое файла определяются перед компиляцией FPGA.
Формат файла Core List предопределен:
- Каждая строка текстового файла описывает инстанцирование ядра в FPGA
- Каждая строка должна содержать 8 полей, как показано в примере ниже.

|Тип ядра Nr|Номер экземпляра ядра|Номер версии|Нижняя граница диапазона адресов|Верхняя граница диапазона адресов|Номер прерывания|Чувствительность прерывания|Magic word (максимум 36 ASCII символов, опциональное поле)|
|--------|--------|--------|--------|--------|--------|--------|------------------------------------|
|00000001|00000002|00000003|10000000|1000FFFF|0000001A|00000001|Core Type Example 1|

- Шаблон формата файла можно найти в [Core List Template](Additional%20Files/CoreListTemplate.txt).
- Первые 7 полей — это 8-значные HEX значения, разделенные символом 'пробел'. (без префикса "0x", см. также [Глава 4.1](#41-text-file-parsing))
- Последнее поле ('Magic Word') — это опциональное краткое описание экземпляра в виде ASCII текста. Оно может содержать до 36 символов.
- Пустые строки (начинающиеся с символов 'CR', 'LF', 'NUL', 'HT' или ' '), или строки-комментарии (начинающиеся с "--" или "//") пропускаются.

Ядро Core List добавит недопустимый Тип ядра Nr ("00000000") как индикацию для CPU, что чтение Core List завершено.

### 2.3 Содержимое Core List
Некоторые **Типы ядер** предопределены:

|Ядро|Тип ядра Nr (hex)|
|--------------------------|:------:|
|Invalid/End                         |0x00000000|
|TC Core List Core Type              |0x00000001|
|TC Adjustable Clock Core Type       |0x00000002|
|TC Signal Generator Core Type       |0x00000003|
|TC Signal Timestamper Core Type     |0x00000004|
|TC PPS Generator Core Type          |0x00000005|
|TC Frequency Counter                |0x00000006|
|TC Clock Detector Core Type         |0x00000007|
|TC SMA Selector Core Type           |0x00000008|
|TC PPS Source Selector Core Type    |0x00000009|
|TC FPGA Version Core Type    		 |0x0000000A|
|TC PPS Slave Core Type    			 |0x0000000B|
|TC ToD Slave Core Type				 |0x0000000C|
|TC Dummy Axi Slave Core Type        |0x0000000D|
|Xilinx AXI PCIe Core Type           |0x00010000|
|Xilinx AXI GPIO Core Type           |0x00010001|
|Xilinx AXI IIC Core Type            |0x00010002|
|Xilinx AXI UART Core Type           |0x00010003|
|Xilinx AXI HWICAP Core Type         |0x00010004|
|Xilinx AXI QUAD SPI FLASH Core Type |0x00010005|

**Номер экземпляра ядра** указывает номер инстанцирования типа ядра, начиная отсчет с "0".

**Номер версии** обычно представлен в формате 0xMMmmBBBB, где MM — старшая версия (8 бит), mm — младшая версия (8 бит), BBBB — сборка (16 бит). Если для версии ядра используются только 2 байта, то номер сборки считается "0".

**AddressRangeLow** — это адрес смещения AXI slave ядра, а **AddressRangeHigh** — это наивысший адрес AXI slave ядра.

Текущая архитектура может предоставлять до 32 прерываний. **Номер прерывания** имеет диапазон 0x0-0x1F, а значение 0xFFFFFFFF используется, когда ядро не отправляет прерываний.

**Чувствительность прерывания** содержит информацию о прерывании ядра.
- Когда bit0 равен "0", прерывание является Edge. В противном случае прерывание является Level
- Когда bit1 равен "0", прерывание активно по низкому уровню. В противном случае прерывание активно по высокому уровню.

**Magic Word** — это краткое представление экземпляра ядра в символах ASCII (максимум 36 ASCII символов, по умолчанию).

## 3. Набор регистров
CPU получает Core List путем доступа к регистрам с отображением в памяти ядра Core List.
Каждый экземпляр ядра выделяет предопределенный диапазон адресов из 16 x 32-битных слов (64 байта адресного пространства на ядро в ROM). Экземпляры ядер хранятся в ROM в соответствии с порядком, указанным в текстовом файле. Для согласованности инстанцирование Core List должно всегда быть первым экземпляром, указанным в файле, и **адресное пространство CoreList должно быть зафиксировано на диапазон [0x01300000-0x0130FFFF]**.
**CPU должен начинать чтение с базового адреса Core List (0x01300000) и останавливать обращения при чтении недопустимого Типа ядра Nr (0x000000).**
### 3.1 Обзор набора регистров
Тип ядра Nr каждого экземпляра ядра всегда хранится по адресам **[0x01300000 + N*(0x40)]**, где **N** — N-й экземпляр, как определено в текстовом файле Core List.

## 4 Описание архитектуры
Ядро Core List состоит из 2 основных частей:
- доступ к текстовому файлу и загрузка его в ROM (во время компиляции)
- AXI4L slave, который предоставляет содержимое ROM CPU

### 4.1 Разбор текстового файла
Функция, которая обращается к текстовому файлу (его путь предоставляется как конфигурация во время компиляции), ожидает определенный формат. В противном случае сообщается об 'ошибке'. Разбор файла выполняется построчно и завершается при достижении EOF.
Допустимый формат каждой текстовой строки:
- строка начинается с CR, LF, HT, NUL, ' '. Строка пропускается
- строка начинается с символов комментария "--" или "//". Строка пропускается
- строка с описанием ядра должна содержать
  - символы 1-9 — это 8-значное HEX значение (символы '0'-'9' или 'A'-'F' или 'a'-'f'), за которым следует символ пробела (' ') (**Тип ядра Nr**)
  - символы 10-18 — это 8-значное HEX значение (символы '0'-'9' или 'A'-'F' или 'a'-'f'), за которым следует символ пробела (' ') (**Номер экземпляра ядра**)
  - символы 19-27 — это 8-значное HEX значение (символы '0'-'9' или 'A'-'F' или 'a'-'f'), за которым следует символ пробела (' ') (**Номер версии ядра**)
  - символы 28-36 — это 8-значное HEX значение (символы '0'-'9' или 'A'-'F' или 'a'-'f'), за которым следует символ пробела (' ') (**Нижняя граница диапазона адресов**)
  - символы 37-45 — это 8-значное HEX значение (символы '0'-'9' или 'A'-'F' или 'a'-'f'), за которым следует символ пробела (' ') (**Верхняя граница диапазона адресов**)
  - символы 46-54 — это 8-значное HEX значение (символы '0'-'9' или 'A'-'F' или 'a'-'f'), за которым следует символ пробела (' ') (**Номер прерывания**)
  - символы 55-62 — это 8-значное HEX значение (символы '0'-'9' или 'A'-'F' или 'a'-'f') (**Чувствительность прерывания**)
  - символ 63 должен быть либо специальным символом NUL/LF/CR/HT (что приведет к завершению обработки строки и переходу к следующей), либо символом пробела (' '), что будет означать, что символ строки является началом опционального поля Magic Word
  - символы 64-99 — это опциональное текстовое поле длиной до 36 символов. Текст разбирается посимвольно, и разбор завершается, когда специальный символ укажет на конец строки, или когда разобрано 36 символов. Любой дополнительный текст в файле будет проигнорирован (усечен). (**Magic Word**)

 ### 4.2 AXI slave
Ожидается, что CPU будет последовательно считывать содержимое ROM, начиная с Базового Адреса и завершая при чтении недопустимого Типа ядра Nr ("0x00000000").
Обращения CPU к AXI для чтения имеют ширину 32 бита. Они должны обращаться к выровненным по слову адресам (выравнивание по 4 байта). В противном случае FPGA автоматически предоставит содержимое выровненного по слову адреса. Например, обращение на чтение по адресу [0x01300004] предоставит данные адресов [0x01300004]-[0x01300007]. Обращения на чтение по адресам [0x01300005], [0x01300006] и [0x01300007] также предоставят те же данные. Это соответствует спецификации AXI4L.
