## 1. Context Overview
PPS Slave — это полностью аппаратная (только FPGA) реализация, которая вычисляет коррекции смещения (offset) и дрейфа (drift), применяемые к локальным часам, для синхронизации с входом PPS. 
При получении PPS снимается метка времени (timestamp) и импульс оценивается. 
Если ширина и период импульса корректны, то вычисляются коррекции смещения и дрейфа локальных часов относительно входа PPS. 
Для сглаживания коррекций локальных часов используются PI-сервоконтуры. PPS Slave конфигурируется и контролируется через интерфейс ведомого AXI4L.

## 2. Interface Description
### 2.1 PPS Slave IP
Интерфейс PPS Slave:
- System Reset и System Clock на вход
- Вход высокоразрешающих часов, для высокоточных меток времени (целое кратное System Clock, с фиксированным соотношением к System Clock)
- Вход локального времени, от [Adjustable Clock](../AdjustableClock/Readme.md)
- Вход события, для которого будет сниматься метка времени
- Входные значения коэффициентов PI для опционального обновления значений по умолчанию
- Вычисленные коррекции смещения и дрейфа на выход, для применения к [Adjustable Clock](../AdjustableClock/Readme.md)
- Интерфейс ведомого AXI4L, через который CPU читает и записывает регистры ядра
 
![PPS Slave IP](Additional%20Files/PpsSlave_IP.png) 

Параметры конфигурации ядра:
- Период системного тактового сигнала в наносекундах.
- Множитель частоты высокого разрешения, показывающий, во сколько раз тактовый сигнал высокого разрешения быстрее системного.
- Опция включения/отключения компенсации задержки кабеля. Если включена, метка времени PPS будет компенсировать задержку кабеля (задаётся в наносекундах через интерфейс AXI4L). 
- Входная задержка в наносекундах, которая будет компенсироваться меткой времени PPS (например, для буферов, всегда положительная).
- Полярность входа PPS. Если '1', то метка времени снимается по фронту импульса. Иначе — по спаду.
- Значения по умолчанию коэффициентов для PI-сервоконтуров смещения и дрейфа, где:
    - Коэффициент I смещения: *K<sub>I_Offset</sub> = (OffsetMultiplyFactorI/OffsetDivideFactorI)\*2<sup>16</sup>*
    - Коэффициент P смещения: *K<sub>P_Offset</sub> = (OffsetMultiplyFactorP/OffsetDivideFactorP)\*2<sup>16</sup>*  
    - Коэффициент I дрейфа: *K<sub>I_Drift</sub> = (DriftMultiplyFactorI/DriftDivideFactorI)\*2<sup>16</sup>*
    - Коэффициент P дрейфа: *K<sub>P_Drift</sub>= (DriftMultiplyFactorP/DriftDivideFactorP)\*2<sup>16</sup>*

## 3. Register Set
Это набор регистров PPS Slave. Доступ осуществляется через AXI4 Light Memory Mapped. Все регистры 32-битные, не поддерживаются пакетный доступ, невыровненный доступ, byte enables, таймауты. 
Адресное пространство регистров не является непрерывным. Адреса регистров — это только смещения в области памяти, где ядро отображено в AXI inter connects. 
Обращение к несуществующему регистру в отображённой области памяти возвращает ошибку декодирования ведомого.

## 4 Design Description
PPS Slave принимает вход PPS в качестве опорного для локального времени и вычисляет коррекции смещения и дрейфа, применяемые к локальному времени.
Ядро состоит из 4 основных операций:
- Снятие метки времени (timestamp) входа PPS по настраиваемому фронту (полярности) с тактовым сигналом высокого разрешения, включая компенсацию возможных задержек кабеля и входа.  
- Валидация входа PPS. Если формат импульса не соответствует ожидаемому, метка времени игнорируется.
- Вычисление коррекций смещения и дрейфа, включая PI-сервоконтуры.
- Интерфейс AXI4L для конфигурации и контроля ядра. 

### 4.1 PPS timestamp with the high resolution clock
Частота тактового сигнала высокого разрешения является целым кратным частоты системного тактового сигнала (задаётся в конфигурации). Тактовый сигнал высокого разрешения используется для уменьшения джиттера метки времени. 
Метка времени снимается при обнаружении фронта PPS. Полярность фронта задаётся через конфигурацию.
При обнаружении настроенного фронта PPS тактовый сигнал высокого разрешения фиксирует событие в сдвиговом регистре. 
Сдвиговый регистр копируется в домене системного тактового сигнала, и таким образом «окно» высокого разрешения может быть определено и соответственно компенсировано.
Для более точного вычисления момента события PPS компенсируются следующие задержки:
- **задержка высокого разрешения**. Как описано выше, снятие метки времени с тактовым сигналом высокого разрешения уменьшает джиттер метки времени, вычисляя задержку высокого разрешения. 
Эта задержка включает смещение регистра для переключения между доменами часов и разницу между фронтом системного тактового сигнала и тактового сигнала высокого разрешения в момент события.  
- **входная задержка**. Она предоставляется в качестве параметра конфигурации ядра на этапе компиляции. Может быть только положительным значением.
- **задержка кабеля**. Она предоставляется в качестве параметра конфигурации через регистр AXI, при условии что компенсация задержки кабеля включена. Может быть только положительным значением.

### 4.2 Validate the PPS input
Ядро проверяет формат входа PPS и выставляет сигналы ошибки при обнаружении неверного формата. 
Вход PPS проверяется по:
- его периоду
- его ширине импульса (скважности)

При обнаружении нового входа PPS запускается свободно работающий таймер, считающий миллисекунды до обнаружения следующего входа PPS (или до достижения максимально допустимого значения). 
Значение этого таймера указывает период входного импульса. 
Ожидается, что период импульса составляет ~1 секунду. То есть существует допустимое временное окно около 1 секунды, в настоящее время установленное в 100 мс. 
Если таймер периода выходит за пределы ожидаемого временного окна (то есть новый вход PPS получен слишком рано или слишком поздно относительно предыдущего), то:
- метка времени импульса игнорируется 
- липкая ошибка периода сообщается в регистр статуса AXI4L (см. Регистр 2 [Главы 3](#3-register-set))

Кроме того, при обнаружении нового входа PPS запускается свободно работающий таймер, считающий миллисекунды, пока импульс активен (или до достижения максимально допустимого значения). 
Значение этого таймера указывает ширину импульса входного сигнала. 
Ширина импульса должна находиться в определённых пределах, в настоящее время установленных от 1 мс минимум до 999 мс максимум. 
Если ширина импульса выходит за границы, то в регистр статуса AXI4L сообщается липкая ошибка ширины импульса (см. Регистр 2 [Главы 3](#3-register-set))

*Примечание*: для избежания ошибок инициализации, когда ядро PPS включено (см. Регистр 1 [Главы 3](#3-register-set)), вход PPS будет игнорироваться до обнаружения 2 активных фронтов входа PPS.

### 4.3 Offset and Drift correction calculation
Вычисление смещения и дрейфа локальных часов относительно входа PPS выполняется в 2 этапа. 

Сначала смещение и дрейф вычисляются относительно метки времени PPS. 
Смещение метки времени PPS — это разница между меткой времени и ближайшей сменой секунды (то есть положительное смещение, если метка снята после новой секунды, отрицательное — если до).
Дополнительно вычитается окончательное вычисление текущего дрейфа. Дрейф — это отклонение 1 секунды от разницы двух последовательных меток времени, за вычетом предыдущего смещения, нормализованное на интервал между двумя метками.

Вычисленные коррекции смещения и дрейфа подаются на 2 PI-сервоконтура для введения плавных коррекций в локальные часы.

### 4.4 AXI slave of the PPS Slave 
PPS Slave включает ведомый AXI Light Memory Mapped. Он обеспечивает доступ ко всем регистрам и позволяет конфигурировать PPS Slave. AXI Master должен конфигурировать наборы данных записью в регистры через AXI, что обычно выполняется CPU. 
Также предоставляется интерфейс статуса, позволяющий контролировать состояние модуля снятия меток времени. Полное описание набора регистров приведено в [Главе 3](#3-register-set).
